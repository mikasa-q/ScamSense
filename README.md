# ScamSense（拆招）

AI 多角色求职反诈模拟训练系统。用户在同一聊天界面中分别与林悦、陈浩和王宇交流，通过提问、核实与决策练习识别招聘风险，并获得有行为证据的复盘报告。

## 本机演示

用 Python 3.12、uv 和 Node.js 22.12+，在仓库根目录分别打开两个终端。

```sh
cd backend
uv sync --locked --python 3.12
uv run alembic upgrade head
uv run uvicorn app.main:app --host 127.0.0.1 --port 8000
```

```sh
cd frontend
npm ci
npm run dev -- --host 127.0.0.1 --port 5173 --strictPort
```

打开 <http://127.0.0.1:5173>，确认使用虚构资料并点击“开始训练”。验收时逐一切换三位联系人，应能读到各自的开场。刷新同一标签页，应恢复这次训练。后端验收运行 `cd backend && uv run pytest`，前端构建运行 `cd frontend && npm run build`。

在王宇的私聊发送“你亲自核实过吗？”，可以看到他说明校园群消息的来源及核实情况。切到林悦后询问“我刚才问了什么？”，她只引用自己这段私聊。默认使用剧情预设回复，运行演示无需模型密钥。

向陈浩发送“我对这个岗位感兴趣”会收到预登记邀请。试着回应“简历不交但项目经历可以聊”，再询问“谁在收资料？”或“保存多久？”。已讨论的项目和实际披露的线索各有原话可查。第二层资料的自动切换等待业务确认。

点击“作招聘决定”并确认一个选项，或单独确认“提前结束训练”，即可查看复盘。复盘分开显示用户原话、角色披露和决定理由。同标签页刷新可重读原报告。候选量表获批前，各维展示证据和无法评分的原因。

在角色答复旁点击“引用”，可以就该条消息写下自己的判断。例如王宇说明未经核实后，写“你没有亲自核实，所以群消息不足以证明岗位可靠”。复盘会并列呈现这条判断与所据的角色原话。

在同一段私聊点“作招聘决定”时，也可选择自己先前的一条发言作为理由。确认后，“决策合理性”会列出这条原话，并可点回它所在的对话。

在复盘点“查看对话原文”可回到该消息及前后文。同一标签页刷新会保留定位。引用地址只含消息标识，读取原文仍需当前标签页保存的训练凭证。

向陈浩说“我打算去官网核对资料收集主体”，再问“能提供独立核对的官方渠道吗？”。结束后，在“主动核实”中可分别查看计划原话、实际请求及该请求收到的答复。

私聊期间可点“暂停训练”。同一标签页刷新后仍显示暂停时的阶段，点“恢复训练”可接着原对话。聊天里暂缓某项资料时可以继续核实。

### 可选模型回复

启动后端前，仅在后端环境设置 `MODEL_BASE_URL`（兼容接口的 HTTPS 地址，通常以 `/v1` 结尾）、`MODEL_NAME` 和 `MODEL_API_KEY`。新建训练时可另行勾选模型选项。服务只发送当前角色最近八条私聊、本次问题与本轮获准用语。模型可据此组织回复，后端核对披露片段并写入证据。超时或答复越界时页面会标明本轮使用剧情预设。可用 `cd backend && uv run pytest tests/test_model.py -q` 通过本地兼容服务复现。

## 已确定方案

前端使用 Vue 3、TypeScript、Vite、Element Plus、Vue Router 和 Pinia，构建为静态资源并发布到 Qoder Sites。后端使用 Python、FastAPI、Pydantic、SQLAlchemy 2.x、SQLite 和 Alembic，在腾讯云 CVM 上由 Nginx、Uvicorn 和 systemd 运行。普通请求使用 HTTPS REST，角色回复使用 SSE；模型通过后端统一调用 OpenAI 兼容 API。

剧情状态由规则引擎控制，三个角色使用独立 Prompt 和独立上下文。评估基于实际行为和可追溯证据，四维权重为风险识别 25%、主动核实 30%、决策合理性 25%、证据分析 20%。
