# P0 主线与分支纸面走查

> 状态：已完成现有资料的约束走查；事件条件和评分结果待负责人补充，未执行应用测试。来源：[原主线](characters-and-story-v1.0.md)、[架构草案](../architecture.md)、[PR1 评审](../reviews/pr1-p0-request.md)。

本文件覆盖评审要求的八类路径。表中阶段只用于解释现有故事，不是实现后的状态迁移测试，也不把未定义 E 事件填入任何节点。用户有跳过、提前核实和退出的权利；具体触发条件不能从剧情顺序猜测。

## 1. 走查前提

- 三个角色只知道自身获准信息；转述按[可见矩阵](role-visibility.md)处理。
- 原主线有 S0 初识、S1 了解、S2 预登记、S3 风险线索、S4 核实、S5 决策、S6 复盘；不按聊天轮数推进。
- [事件表](events.md)全部未冻结，[线索表](clues.md)只有五类已有主题，[字段表](data-fields.md)缺少额外资料定义，[评分](scoring-rubric.md)没有获批分档。
- 用户样例均为虚构对话材料，不构成新增风险事实；以下“核对通过”只指文档约束一致，不能等同于系统已经运行通过。

## 2. 八类必查路径

| 路径 | 给定与用户行为 | 已有设计允许核对的结果 | 线索、角色与证据核对 | 当前验收结论 / 缺口 |
|---|---|---|---|---|
| F01 正常推进完整流程 | 用户了解岗位，对陈浩机会感兴趣，讨论已列模拟资料，遇到已有风险主题后核实并明确决策 | 主线覆盖 S0–S6，正常 HR 提供参照，陈浩不一开始自曝，复盘引用实际行为 | 只记录真实出现的片段和用户行为；不能为了完整流程擅自补上额外字段 | 主线一致；E 映射、各次触发、额外字段和评分缺失，完整流程验收待补 |
| F02 一开始主动核实 | S0/S1 用户即问招聘主体或独立渠道 | 允许提前核实，不要求凑轮数或先提交资料；S0/S1 → S4 是架构现有草案，精确里程碑语义待确认 | 不能因提前核实一次就披露全部线索，不能把其他私聊注入当前角色 | 非强制顺序原则一致；事件条件与随后可继续的分支待 P0-Q01/Q05 |
| F03 拒绝提供资料 | 用户拒绝一个字段、表示暂缓，或明确选择退出 | 陈浩尊重拒绝、不骚扰；不能把局部拒绝自动改成全局终结或反过来 | 不替用户补写拒绝理由；其他角色不会自动得知这次拒绝 | 约束一致；局部拒绝/最终拒绝/暂缓/暂停的精确区分待 P0-Q03/Q05 |
| F04 未回应风险线索 | 假设用户已能查看某获准片段，继续聊岗位却未提及风险 | 保留已发生的对话；不让模型代替用户识别或自动推进终局 | 先区分可查看、已展示与实际表达；没有表达不能证明其内心忽略，分数也不能按轮数补造 | 披露与识别分离成立；观察机会及评分口径待 P0-Q02/Q04 |
| F05 向朋友求证 | 用户问王宇信息从哪来、有没有亲自核实 | 王宇只能基于有限见闻，追问时承认未核实；不编造成功入职 | 陈浩/林悦不自动听到这段；用户再主动转述给谁，谁才能基于转述回应 | 知识边界一致；“室友”措辞、事件条件和用户后续分析分值未定 |
| F06 只识别部分风险 | 用户对实际出现的主体疑点作出分析，未分析其他线索 | 只写已表现出来的能力；不宣称全部识破，也不把从未披露的线索写成漏看 | 每个识别候选都关联原话及材料；其余分别标未出现、展示未知或未观察到表达 | 证据边界一致；部分识别分档、适用范围、总分显示规则待 P0-Q04 |
| F07 提前结束 | 用户在关键剧情完成前明确结束；可能有或没有此前分析 | 允许退出，复盘只使用已有记录；不得自动补完剧情或替其选择“已识破后拒绝” | 结束命令与最终招聘选择不同；仅有退出不能推断理由和证据分析 | 提前结束原则一致；S5/S6 的细化、undecided 草案及 null 门槛待 P0-Q04/Q05 |
| F08 角色回复异常/模型不可用 | 本轮未得到有效回复，或只收到部分获准片段 | 不让异常回复改写关键状态；明确说明中断/不可用，不编造成功回复 | 未输出的草稿不记披露；已有可查看片段不能抹去；系统故障不能算用户漏识别 | 约束一致；具体恢复实现留待后续，事件失败效果仍需 P0-Q01 |

## 3. 交叉风险走查

| 风险 | 走查检查点 | 本次发现与处理 |
|---|---|---|
| 无法继续 | 提前核实后还能否正常问岗位、拒绝局部字段后是否仍能交谈 | 现有原则支持自由提问，但事件条件缺失，不能证明不存在死路；列入 P0-Q01/Q05 |
| 重复触发/重复计分 | 重复兴趣表达、反复问用途、相同决定重复提交 | 幂等和不能按次数评分的边界保留；逐事件重复策略及条目去重待确认，不能“每问一次都解锁/加分” |
| 状态冲突 | 同时表达“想继续但先别收资料”，或一段话同时拒绝部分字段与表示兴趣 | 不擅自替用户选择终结；架构澄清/明确命令是现有草案，业务优先级需负责人确认 |
| 提前泄露 | 初始阶段读取完整事件/风险答案；全局到 S3 就给全角色解锁 | 不允许；阶段不是全量授权，具体获准片段仍需逐事件填写 |
| 角色越权 | 林悦主动揭穿陈浩，王宇给不存在的入职证明，角色读取其他私聊 | 与原角色卡直接不符；保留禁止边界，不新增例外 |
| 虚构资料需求 | 用未知额外字段凑出风险事件 | 不允许补造；该分支明确待输入，真实敏感信息始终不收集 |
| 评分“看似完整” | 把最终拒绝判满分、全部未知记 0、把朋友发言当用户能力 | 无证据不能给分；量表未冻结时不显示自拟数字 |
| 断流证据丢失 | 已显示半段线索后中断却把线索重置为未披露 | 与既有架构约束不符；保留实际发生的证据，但具体失败事件效果仍需填写 |

本次确认了应防止的错误类型，**没有因列出处理原则就宣称运行系统不存在这些缺陷**。需要完整事件及量表后，再用确定输入和期望结果重新走查。

## 4. 匿名会话体验核对

这是对评审要求的客户端行为说明，不创建页面、存储代码或新 API。完整说明见架构 §11.1.1。

| 路径 | 应说明的行为 | 评审状态 |
|---|---|---|
| U01 创建成功 | 前端在进入训练前立即保存会话 ID 与令牌；不写 URL、日志或普通业务消息 | S2 已要求；保存失败应明确提示，不能悄悄反复新建 |
| U02 同标签页刷新 | 使用 sessionStorage 中有效凭证恢复当前会话和历史；若创建仍未确认，恢复“结果待确认”提示并沿用原请求标识 | 与现有方案兼容，不能在每次页面初始化自动创建新会话 |
| U03 创建请求超时/响应丢失 | 明确告知结果未知，禁止自动换新标识循环创建；原标识重试不应泄露已有令牌；另开新训练须用户明确操作 | 与既有幂等/一次性令牌草案衔接，精确界面文案待确认 |
| U04 关闭后再次打开或凭证缺失 | 现有方案不保证关闭后凭证可恢复；无凭证不访问旧会话，不提供找回或多设备同步 | 是否要求跨关闭保留为 P0-Q07；浏览器可能恢复标签页储存，因此也不能承诺关闭立即删除服务端数据 |

## 5. 走查结论

八条业务路径和四条会话体验路径均已在文档中覆盖；核心隔离、非轮数推进和证据边界可以保持。事件依赖图、逐条触发结果、必要字段、分数/null 判定仍无法验收，不能声称 P0 已冻结。
