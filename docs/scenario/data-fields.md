## 4. 用户拒绝或追问时的处理边界

| 用户行为 | 已有约束 | 待确认的业务分支 |
|---|---|---|
| 追问字段用途/接收方/期限 | 角色按自己的事实回应；林悦解释正常流程，陈浩只能给预设范围内的有限说明 | 每字段实际说明、可披露线索、触发事件与后续阶段 TODO |
| 拒绝某项模拟资料 | 不能强迫提交真实信息；陈浩尊重拒绝，不持续骚扰 | 能否只填必要字段、继续问岗位、自动转入决策或保持当前会话，需 P0-Q05 确认，不替用户自动选择 |
| 暂缓提交、要求先核实 | 原主线允许核实、暂缓 | 是否仅暂停资料流程或终结训练必须区分，不能凭“暂缓”一词推定最终决定 |
| 同意预登记 | 只证明当前表达的意愿 | 不能推断同意全部额外字段、第三方处理或长期保存 |
| 只提交最小模拟资料 | 原主线有“仅提交必要资料”的最终选项 | 哪些字段属于必要、具体判断和评分尚未冻结 |
| 输入疑似真实敏感资料 | 训练仅使用虚构内容，不要求真实资料 | 输入保护属于已有架构安全约束；本次不实现检测代码或新增登记字段 |

## 5. 核对示例

- 仅看到“专业”或“可实习时间”，不能直接认定风险；应核对用途和必要性。字段级风险等级仍为 TODO。
- 用户问“所在城市填到什么程度”，应保存实际问题，不能当成对资料接收方的核实，也不能引导其填写家庭住址。
- 用户拒绝提供某项资料，不能让王宇突然知道这次私聊并劝填；无用户转述或明确授权事实时，角色隔离继续成立。
- 对未定义额外字段，走查结果是“缺少输入，不能冻结该分支”，不是让角色自行补全后宣称流程已验收。

结论：普通资料具备现实合理性的设计方向保留；用途、必要性、风险和时机需要逐项有依据。P0-Q03 未解决前，不具备构造正式登记规则的条件。
