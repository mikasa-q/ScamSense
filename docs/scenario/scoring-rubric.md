# P0 四维评分依据与量表待确认项

> 状态：**权重已确认；可执行数字量表未提供，尚未冻结。** 依据：[PR1 评审 §二.4、§三 P0.5、§五](../reviews/pr1-p0-request.md)、[原剧情的训练目标与复盘](characters-and-story-v1.0.md)。

评审要求评分落到判据，同时明确禁止自行创造评分规则。现有资料只有权重、证据原则和评价方向，没有获批的条目分值或分档。因此本文完整整理观察材料、规则填写要求、无法评估情形和每维三个边界案例；**不自行设置“问一次加几分”“识别一个风险算哪个档”或优秀/合格分数线**。所有数字评分需项目负责人补充或批准后才可冻结。

## 1. 已确认内容与未确认内容

| 维度 | 已确认权重 | 已有评价方向 | 未确认项 |
|---|---:|---|---|
| 风险识别 | 25% | 指出招聘主体、资料用途/必要性、处理透明度等风险 | 每条判据、部分识别如何得分、严重程度是否影响分值 |
| 主动核实 | 30% | 主动问用途、关系、来源、官方渠道等，并记录实际行动 | 具体提问门槛、追问是否必要、计划/请求/执行/结果如何分别计分 |
| 决策合理性 | 25% | 判断最终选择及理由是否与已掌握证据一致 | 各选择的适用条件、无理由/早退/有限资料策略如何评分 |
| 证据分析 | 20% | 区分口头保证、朋友印象、可验证事实及证据缺口 | 论证充分程度、引用要求、错误推论及不同档位边界 |

架构中“每维 0–100”和加权总分公式是既有技术草案，不包含具体评分量表，也不是本次新批准的分档。四个权重不变；不把严重程度、聊天轮数、关键词频次或未映射的 E 编号当成现成分值。

## 2. 风险识别

| 要素 | 现有资料允许整理的内容 |
|---|---|
| 评价目标 | 是否基于实际线索指出风险或证据缺口，而非靠角色性格或薪资猜身份 |
| 可观察行为 | 用户提及具体收集主体、资料、用途、期限/接收方或核实依据，并说明担忧所在 |
| 正向观察材料 | 用户明确指出已出现的主体关系不清、用途解释不足或朋友背书未经核实；原话能关联实际消息 |
| 反向/不足材料 | 只说“热情就是骗子”“薪资高所以可疑”；不能从这些表达直接确认识别了已定义风险。沉默也不能直接视为失败，先核对观察机会 |
| 分档标准/分值区间 | **TODO：未提供。** 单条识别、多条识别、只提及未分析、部分错误如何区分，需要负责人批准 |
| 不直接赋分的情形 | 角色自己披露风险、模型替用户总结、只命中关键词、反复重复同一质疑、没有实际消息支持的猜测 |
| 引用要求 | 用户原话及位置、关联角色消息、线索来源/展示依据、是否只是预防性询问；不引用模型内部推断充当用户证据 |

| 案例（仅为评审样本） | 可确认的记录 | 无法自动确定的得分 |
|---|---|---|
| R01：用户只问“公司叫什么” | 存在主体信息询问 | 不足以宣称已指出主体不透明；是否核实得分需主动核实判据 |
| R02：用户根据实际回复指出主体关系不明，但未提及其他线索 | 保存这一具体分析及所依赖消息 | 部分风险如何计分、其他线索是否有观察机会都待确认，不能直接满分或把未知项计错 |
| R03：用户仅因陈浩热情或岗位薪资而拒绝 | 保存拒绝及原理由 | 不能替其补写主体/用途风险分析；无获批量表，不填造 0 分或其他分数 |

## 3. 主动核实

| 要素 | 现有资料允许整理的内容 |
|---|---|
| 评价目标 | 是否主动核对来源、主体关系、资料用途或独立渠道，关注过程而非问题数量 |
| 可观察行为 | 有明确对象的用途询问、来源追问、独立渠道请求、对含糊回复的后续核对 |
| 正向观察材料 | “这些资料用于哪一步”“你亲自核实过吗”“如何通过独立官方渠道核对”等实际请求；有模拟核实结果时另记来源 |
| 反向/不足材料 | “你觉得呢”只求看法；“我以后会查”只是计划；接受口头保证不能证明已核实；重复提问不自动增加新证据 |
| 分档标准/分值区间 | **TODO：未提供。** 一次具体用途询问是否即可计分、是否需追问、核实成功与尝试如何区分必须明确 |
| 不直接赋分的情形 | 角色主动提供信息而用户未行动、复制模型建议但未表达自己的请求、仅询问填写位置或格式 |
| 引用要求 | 核实问题原文、对象、发送给哪个角色、角色回复、后续行动及模拟结果（如存在）；区分请求与完成 |

| 案例（仅为评审样本） | 可确认的记录 | 无法自动确定的得分 |
|---|---|---|
| V01：用户问“这些资料具体用来做什么”，没有后续追问 | 一次明确用途请求，属于可供核实判据使用的观察材料 | 达到何种程度计分未提供，不能直接设定基础分或满分 |
| V02：用户重复同一个问题三次，未加入新对象或分析 | 三条实际输入，但不伪装成三种独立核实能力 | 重复证据去重单位和分值封顶 TODO，不能按次数累加 |
| V03：用户说“我会去官网查”，或实际向角色要求独立官方渠道 | 前者是计划，后者是请求，均不等于已经完成查证 | 是否分别计分、如何证明执行待确认；渠道本身未配置时不得编造验证结果 |

## 4. 决策合理性

| 要素 | 现有资料允许整理的内容 |
|---|---|

| 反向/不足材料 | 只有选择没有理由、理由引用不存在事实、把岗位待遇或朋友印象当充分证明；但不能代替用户推定动机 |
| 分档标准/分值区间 | **TODO：未提供。** 继续/拒绝并不天然对应固定好坏分，早退和仅必要资料需业务前提 |

## 7. 无法评估与总分

| 情形 | 可明确的报告边界 | 仍需冻结的决定 |
|---|---|---|
| 当前缺少获批量表 | 不能输出自拟分数；说明量表未冻结，不把它描述为用户表现差 | 全部量表条目及版本 |
| 用户提前退出、关键线索未出现 | 保留实际行为；未披露不等于忽略，不靠轮数判定 | 哪些维度仍足够评价、总分是否可显示及门槛 |
| 线索已可查看但无展示依据 | 说明展示情况未知，不编造用户已阅读 | 观察机会的认定标准 |
| 用户只拒绝且无理由 | 选择可记录，理由和分析不能猜测；允许 null/无法评估 | 决策维度的最低证据要求 |
| 只识别部分风险 | 按实际证据说明已指出与未观察项，不擅自均分五类线索的分值 | 部分识别分档、适用项、严重程度关系 |
| 引用不存在或与本次训练无关 | 不认可为可追溯得分依据，不用模型补造消息 | 条目级验证和异常处置细则 |
| 模型/服务异常造成证据缺失 | 区分系统异常与用户没有行为，不把异常变成用户扣分 | 恢复后可评价范围；不在 P0 实现容错 |

`null` 表示无法按有效规则评估，不等于 0 分。任何未来总分都必须保持 25%/30%/25%/20% 的已确认权重；不能为了显示一个数字重新分配缺失维度的权重并称为原四维总分。

## 8. 规则与模型职责

所有分项分数、档位、总分、适用性及重复证据处理都必须来自已冻结的确定性规则。LLM 可以提供待校验的意图/证据候选或组织复盘语言，但不得自由选择分值、修改权重、创造用户行为或引用。

模型自报“用户已识破”不是得分证据；正式得分必须回溯到用户原话和相关材料。固定分数及引用形成后，模型润色失败可保留事实性说明，不改变评分。意图阈值、模型格式和具体实现不在本次 P0 新定。

结论：已具备量表评审材料，**尚不具备可执行评分标准**。这项缺口阻止 P0 冻结和进入 P1，不能用“评分文档已创建”替代验收通过。
