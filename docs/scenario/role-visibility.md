# P0 角色可见信息与知识边界

> 状态：现有约束整理，逐事件授权尚未冻结。依据：[原角色卡 §2、§5](characters-and-story-v1.0.md)、[PR1 评审](../reviews/pr1-p0-request.md)。

本文不新增角色或剧情事实。S0–S6 只表示故事阶段；到达某阶段不代表角色自动获知该阶段涉及的所有信息。具体事件授权缺失时，不能推断解锁条件。

## 1. 全阶段不变的边界

| 检查项 | 林悦 | 陈浩 | 王宇 |
|---|---|---|---|
| 自身身份与岗位/关系 | 自己公司 HR、Python 后端实习、自己的正常流程 | 自称招聘顾问及自己获准介绍的岗位；隐藏动机属于原角色设定 | 用户的大学朋友，知道用户在找实习 |
| 陈浩真实身份、隐藏风险与动机 | 不知道，不得自动判断或揭穿 | 不得向用户提前自曝；模型本轮能接收的行为投影待按事件明确 | 不知道，不是故意帮助风险角色 |
| 林悦与用户的私聊 | 仅林悦自己的上下文可用 | 不可读取 | 不可读取 |
| 陈浩与用户的私聊 | 不可读取 | 仅陈浩自己的上下文可用 | 不可读取 |
| 王宇与用户的私聊 | 不可读取 | 不可读取 | 仅王宇自己的上下文可用 |
| 王宇的正面印象 | 未被用户主动转述时不知道 | 未被用户主动转述时不知道 | 来自校园群与有限见闻，未经本人核实；具体“室友”措辞待确认 |
| 系统内部线索、事件条件和评分答案 | 不可读完整配置 | 不可读完整配置；只给获准事实/行为约束 | 不可读完整配置 |
| API Key、令牌、内部异常、他人会话 | 均不可知 | 均不可知 | 均不可知 |

模型输入投影不改变人物设定：陈浩在故事中的隐藏动机与“模型不得收到全部风险答案”可以并存。投影不得以“角色卡写了隐藏动机”为由提前披露，也不得修改原文说陈浩人物不知道自己的动机。

## 2. 分阶段可见信息矩阵

下面的“允许”均以自己角色卡、自己聊天和已授权事实为边界，不授权模型填补公司、官方渠道、额外资料或事件细节。

| 阶段 | 林悦可以知道/回应 | 陈浩可以知道/回应 | 王宇可以知道/回应 | 仍不可知道或自动共享 |
|---|---|---|---|---|
| S0 初始接触 | 自己的岗位介绍与正常招聘参照 | 自己的公开岗位介绍，前期正常沟通 | 求职进展、校园群相关见闻 | 陈浩风险不提前公开；任何其他私聊都不共享 |
| S1 了解机会 | 回答自己岗位、薪资、技术与流程的已知事实 | 回答自己岗位的已知事实，条件不能夸张 | 表达有限印象、承认不专业 | 不知道用户对另一 HR 的提问，不能临时编造地点/公司/证明 |
| S2 候选人预登记 | 仍只处理自己的正常招聘沟通 | 用户对自己岗位表达兴趣后，依已批准顺序讨论登记资料；只用虚构占位内容 | 可基于已知见闻谈看法 | 全局进入 S2 不意味着林悦/王宇知道用户与陈浩登记，也不等于授权所有额外字段 |
| S3 风险线索 | 被询问时解释自己正常流程，不主动替用户下结论 | 按获准线索/事实回应资料、主体、用途等疑问；不自行新增风险要求 | 根据当前对话说明有限信息来源 | 哪个片段可在何时披露仍由待确认事件控制；线索出现不自动同步到所有角色 |
| S4 主动核实 | 可提供自己预设的正常流程与核实渠道；内容未定时不得编造 | 面对主体、用途、期限、接收方及独立渠道询问，只能基于预设事实回应 | 被追问时承认未亲自核实；可随具体证据重新考虑 | 用户向 A 核实不能让 B 获知；看到提问不等于看到另一角色原始证据 |
| S5 最终决策 | 不自动得知用户对其他招聘机会的决定 | 用户明确向其拒绝时尊重决定，不骚扰 | 不自动得知其他私聊结果 | 谁在终结时收到什么通知尚未定义；架构冻结聊天的做法仍是草案，不新增告别剧情 |
| S6 复盘 | 不自动注入完整复盘或其他角色历史 | 不自动获得其他私聊和评分答案 | 不自动获得完整风险真相 | 复盘展示给用户，由系统组织；是否存在角色参与的复盘未提供，不新增该功能 |

提前核实允许在 S0/S1 发生，但不能因此将 S3 全部隐藏内容或所有角色历史注入当前角色。S4 后阶段不回退是架构技术草案，精确业务条件见 [P0-Q05](p0-inventory.md)，本矩阵不替事件表冻结跳转规则。

## 3. 用户主动转述

| 输入情形 | 当前角色可使用的信息 | 不允许的推断/传播 |
|---|---|---|
| 用户对林悦说“另一位招聘顾问让我先登记” | 当前用户转述的这句话；可讨论一般正常流程 | 不得读取陈浩原始消息，不得自动断言陈浩是骗子 |
| 用户对王宇说“对方没有解释资料会给谁” | 用户声称对方解释不足；可重新考虑自己的印象 | 不得编造自己核实过该公司，不把转述变成查证结果 |
| 用户向陈浩转述林悦的流程 | 本次转述内容，保持“据用户所说”的来源 | 不得调取林悦的私聊、证明或用户未转述的资料 |
| 用户给一个角色提供自己的模拟求职信息 | 仅当前角色的用户输入 | 不自动同步其他角色，不形成全局用户档案事实 |
| 用户要求“把别人的聊天全部看一遍” | 仅能解释当前信息边界 | 不改变权限、不请求或拼接其他角色上下文 |

“转述后可回应”只作用于接收该条转述的角色，不是全场共享开关。转述需保留原话及来源；用户声称某件事发生不等于系统确认其真实发生。

## 5. 约束走查示例

| 场景 | 可确认的验收边界 | 未冻结部分 |
|---|---|---|
| 在陈浩私聊输入唯一测试词，再询问林悦该私聊 | 林悦的可见输入不含该词或其他私聊摘要 | 后续工程如何检查 Prompt 留待后续阶段 |
| 用户主动转述上述词给林悦 | 林悦可基于转述回应，但不得声称读过原私聊 | 转述证据的最终存储方式不在 P0 设计 |
| 仅把全局阶段改成 S3 的纸面走查 | 不自动让王宇得知风险真相或收集主体细节 | 具体可见事实缺失，不能宣称逐事件验收通过 |
| 朋友说“看起来不错” | 只代表有限印象，不能作为已核实/成功入职依据 | 不因此直接赋予用户某个分值 |

结论：独立上下文和转述边界已有依据；完整的逐阶段、逐事件事实白名单仍需负责人补齐，当前不能作为全部已冻结的运行 Prompt。
