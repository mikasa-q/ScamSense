# ScamSense MVP 业务规则 v0.1

项目负责人已决定采用精简事件方案 B。以下十个具名事件构成 MVP 初始方案。原 P0 的 E01–E16 登记表留档，MVP 无需补齐旧编号或建立新旧映射。[架构 v1.1 §6–7](../architecture.md) · [角色卡与剧情 v1.0 §2–5](characters-and-story-v1.0.md) · [P0 盘点](p0-inventory.md)

## 四种业务记录

| 记录 | 成立条件与证据 |
|---|---|
| 事件触发 | 后端规则根据当前会话、角色、前置事实和本次输入确认事件成立。保留触发它的用户原话、角色消息或系统操作，只执行事件表中相应的效果。 |
| 角色披露线索 | 获准的角色答复中，实际有哪段内容已进入用户可查看的对话，就记哪段，关联角色、消息和 K 索引。只有披露计划或未发出的草稿时没有披露记录。缺少展示依据时标记“可查看，展示情况未知”。 |
| 用户识别风险 | 用户用自己的话指出具体材料中的疑点或证据缺口。将用户原话与对应材料关联。普通提问、角色主动披露、用户沉默或拒绝资料，单独都不足以认定识别。 |
| 用户最终决策 | 用户通过最终选择操作确认招聘决定时，记录选择、确认操作及其自述理由（如有）。“退出招聘流程”是原剧情的四种选择之一。单独确认“提前退出训练”时，记录结束原因，招聘选择留为“未决定”。 |

例如，用户问王宇“你亲自核实过吗？”时，可以记录追问来源。王宇实际回复自己没有核实过，才形成 K05 披露。用户随后说“那你的印象还不能证明这个岗位可靠”，这句话才提供识别依据。若用户又明确提交“先核实再决定”，才有最终招聘选择。这四项可以各自有证据，也可以只发生其中一部分。

## 十个核心事件

聊天类事件适用于仍可对话的会话。表中的触发与效果依据原剧情整理，未定的具体措辞、披露片段和阶段落点**待负责人确认**。“可关联 K”须另核对角色实际回复。每个角色只使用自己的私聊和获准事实。用户向谁转述，谁才可按该转述回应。[角色可见信息](role-visibility.md)

| 事件 | 触发条件 | 后端确认后的业务效果 |
|---|---|---|
| `SESSION_CREATED` | 用户发起创建，后端成功建立本次训练会话。 | 进入 S0，三角色可各自在私聊开场。同一创建操作只建立一次会话。 |
| `USER_EXPRESSES_INTEREST` | 用户在与陈浩的对话中明确表达对其岗位的兴趣。只问薪资、对林悦的岗位感兴趣均不满足。 | 记录兴趣原话。剧情配置允许引导登记时，S0 或 S1 可进入 S2，已在 S4 时可继续讨论登记。提交意愿由用户另行表达。 |
| `REGISTRATION_REQUESTED` | 已有上述兴趣，陈浩实际向用户提出获准的候选人预登记邀请，该消息已可查看。 | 记录邀请消息及本次已提出的资料范围，供后续回应引用。仅开放当前获准层级。 |
| `USER_RESPONDS_TO_INFO_REQUEST` | 已有具体登记资料请求，用户对其中全部或部分资料明确同意、提供虚构内容、拒绝或暂缓。 | 对照原请求记录所涉项目与回应，区分同意与实际提供。陈浩尊重拒绝，用户可继续提问、核实或作决定。 |
| `USER_ASKS_RECRUITMENT_IDENTITY` | 用户向 HR 核实谁在招聘、谁收资料，或顾问与招聘主体有何关系。 | 记录对象和问题，允许当前 HR 依自身事实答复。陈浩的实际回复若体现主体关系不透明，可关联 K01。 |
| `USER_ASKS_DATA_USAGE` | 用户向 HR 询问资料的用途、必要性、保存期限或第三方处理。可在提交资料前问。 | 按实问事项记录核实行为。陈浩的用途或必要性说明不足可关联 K02，期限或第三方处理说明不清可关联 K03。各自只记实际出现的片段。 |
| `USER_REQUESTS_VERIFICATION` | 用户实际索取可独立核对的官方渠道或依据。仅说“我以后会查”只记录计划。 | 记录核实请求。林悦仅可提供已预设的模拟渠道，具体内容待负责人确认。陈浩答复中体现独立依据不足的片段可关联 K04。核实结果须有另行取得的材料支持。 |
| `USER_CHECKS_FRIEND_SOURCE` | 用户向王宇追问消息来自哪里或他是否亲自核实过。泛问“你觉得呢”只属征求意见。 | 记录来源追问。王宇按有限见闻回应，其实际承认未经核实的片段可关联 K05。 |
| `USER_MAKES_DECISION` | 用户通过最终选择操作确认继续提交、仅提交必要资料、先核实再决定或退出招聘流程。 | 记录唯一最终招聘选择及已有理由，进入 S5，固定截至确认时的证据。 |
| `SESSION_COMPLETED` | 已在 S5，后端已核对固定的证据并保存可查看的复盘。证据不足时可保存写明“无法评估”及原因的复盘。 | 进入 S6。复盘列出已确认的招聘选择，单独提前退出训练时显示“未决定”及结束原因。 |

同一输入重放沿用已有结果。新的追问可留存新的对话证据，重复同一问题不重复计分。陈浩在 S2 问到模拟简历，用户答“简历先不交，你们收它做什么？”，分别记录暂缓和用途核实，按核实进入 S4。同轮答复若披露了获准线索，另记片段，阶段至多推进一次。含义冲突时保留当前阶段并澄清。兴趣的措辞边界、重复登记邀请及同轮阶段转移的细则**待负责人确认**。

## 阶段与分支

S0–S6 是原剧情的七个阶段。下表按架构草案走查进入各阶段的条件，具体落点**待负责人确认**。提前核实或结束时可跳过中间阶段，只记录实际发生的事件。每次披露仍须核对当前角色和获准片段。[架构 v1.1 §6.2–6.4](../architecture.md) · [主线与分支走查](flow-review.md)

| 到达阶段 | 从哪里进入 | 最低条件 |
|---|---|---|
| S0 初始接触 | 新会话 | 后端已成功建立训练会话。 |
| S1 了解机会 | S0 | 用户询问公司名称、岗位、薪资或一般招聘流程。继续了解岗位详情时留在 S1。 |
| S2 候选人预登记 | S0 或 S1 | 用户在陈浩私聊中明确表达对其岗位的兴趣，且剧情配置允许陈浩引导登记。陈浩实际发出的邀请和用户对具体资料的回应分别取证。 |
| S3 风险线索出现 | S2 | 当前角色获准披露的 K01–K05 中至少一段已保存在用户可查看的消息中。只有登记进度或披露草稿时仍在 S2。披露后用户只继续聊岗位，留在 S3。 |
| S4 主动验证 | S0–S3 | 用户已就主体、资料处理、独立渠道或朋友来源提出具体核实问题，也可向林悦核对正常流程作为参照。发出具体问题即可直达 S4。在 S4 补聊岗位、登记或出现新线索都留在 S4。 |
| S5 最终决策 | S0–S4 | 确认招聘选择（含“退出招聘流程”）触发 `USER_MAKES_DECISION`。单独确认“提前退出训练”直接进入 S5，保留“未决定”，不触发该事件。两条路径都结束聊天并固定已有证据。 |
| S6 复盘 | S5 | 可查看的复盘已保存，触发 `SESSION_COMPLETED`，本次训练到此结束。等待生成或生成失败时停在 S5，重试沿用同一份证据。 |

问候、切换角色、重复相同问题、回应或拒绝单项资料、只说打算核实以及聊天轮数增加，本身均不推进阶段。“不想继续了”指向不明时，留在原阶段澄清。聊天中的“先核实再决定”或“退出招聘流程”只记意向，通过最终选择操作确认才进入 S5。单独操作“暂停训练”后，恢复时回到原阶段。

## 风险线索与登记资料

| 沿用的 P0 索引 | 复盘时可引用的角色线索 |
|---|---|
| K01 | 岗位、招聘顾问与实际资料收集主体之间存在信息差异，关系不透明。 |
| K02 | 部分资料的用途解释不足，收集必要性不明确。 |
| K03 | 资料保存期限及第三方处理缺乏清晰说明。只谈到其中一方面时只记录该方面。 |
| K04 | 用户要求官方核实时，陈浩无法提供足够的独立验证依据。 |
| K05 | 王宇承认自己没有亲自核实该招聘机会。 |

原剧情给出了陈浩先后讨论的两层九项资料。下表以原文列序逐项请求，层内顺序、切层及部分拒绝后的处理**待负责人确认**。林悦按自己的正常招聘流程解释合理资料，王宇只分享见闻。[登记资料原表](data-fields.md)

| 登记层级 | 默认请求顺序 | 进入条件 |
|---|---|---|
| 第一层（六项） | 姓名 → 学校 → 专业 → 毕业时间 → 简历 → 项目经历 | 用户已向陈浩明确表达岗位兴趣，陈浩实际发出预登记邀请后，可从姓名开始讨论虚构资料。 |
| 第二层（三项） | 可实习时间 → 所在城市 → 求职意向 | 同时满足两点才切层。① 第一层的每一项都已得到明确回应或被用户明确跳过。② 用户此时明确愿意继续登记。拒绝或暂缓某项也算对该项的回应。 |

“可以登记”只记登记意愿。对已请求的字段分别记同意、实际提供的虚构内容、拒绝或暂缓，沉默的项保留为未回应。例如，前四项已有回应，用户说“简历不交，可以聊项目经历”，就记为拒绝简历，跳过该项，接着问项目经历。只有用户给出模拟项目内容时才记为已提供。

用户限定“只谈这几项”时，只在其允许的范围内按序继续。暂缓整个登记或拒绝其余资料时，陈浩停止索取，用户仍可问岗位、核实或作最终选择。第二层问完即停止索取，讨论完一层本身不推进剧情阶段。

训练只用虚构占位内容，简历只讨论模拟文本。字段名称、岗位待遇和角色态度均不足以独立证明风险，应结合主体、用途及处理说明判断。原文提到但未命名的额外资料**待负责人确认**，本版陈浩的预登记限于表中九项。[风险线索与观察证据](clues.md)

## 四维评分与对话证据

四维各暂定 **0–4 分**。下表的最低证据和相邻档判据**待负责人确认**，获批前只用于纸面走查。逐维核对最低证据，再选原话完整支持的最高一档。同维重复相同证据只判一次。一次发言可支持不同维度，每一维都须指出满足该档判据的原话。[评分材料与边界案例](scoring-rubric.md)

| 候选档位 | 风险识别（25%） | 主动核实（30%） | 决策合理性（25%） | 证据分析（20%） |
|---|---|---|---|---|
| 最低证据 | 用户的风险判断原话及该判断针对的可查看材料 | 用户要核实的具体事项，以及能定位的放弃核实、说明计划、发出请求或模拟核对的原话或操作 | 已确认的招聘选择，以及能明确归属于该选择的用户理由原话 | 用户用某段材料作判断的原话，以及所引材料原文和来源 |
| 0 | 明说仅凭待遇或角色态度就足以断定安全或危险 | 对可核实的具体事项，明说朋友已经背书，可以省去核实 | 选择理由与当时所引材料直接矛盾，例如以“王宇核实过”为由提交，而王宇原话是“没核实过” | 把未经核实的转述明确当作独立证实的结果 |
| 1 | 对一段能定位的登记说明或角色说法表达疑虑，尚未指出缺口 | 说清打算核实什么，尚无实际请求 | 只给出待遇或个人印象作为偏好，未误述所引的事实 | 引用某条说法支持自己的判断，尚未说明来源性质 |
| 2 | 指出哪项关系或说明不清，例如“登记说明没说谁收资料” | 实际询问谁收资料或索取官方渠道等，问题有具体对象，尚未针对已有答复的缺口 | 指出哪条具体疑点影响了选择，例如因收集方不明而选“先核实再决定” | 在自己的判断中说明所引材料是当事人自述、朋友转述还是独立资料 |
| 3 | 引用原话解释缺口的后果，例如收集方不明，提交简历可能使无关人员取得资料 | 指出已有答复哪一点仍不清楚，并就这一点实际追问 | 引用当时的材料解释所选做法怎样应对疑点，例如先核对收集方的授权，可避免把简历交给无关人员 | 解释该来源为何足以或不足以支持某个结论，例如王宇没有亲自核实，他的印象不足以证明岗位可靠 |
| 4 | 在解释风险后，说清材料支持什么、还不能断定什么，以及仍需哪项依据 | 针对已有答复的具体缺口，说清要用什么独立依据核对哪项说法，并实际索取或使用该依据。可按尝试判档，核实结果另行取证 | 在解释应对方式后，指出仍缺哪项依据，以及这项不确定性如何影响当前选择 | 对照至少两段可定位的材料，说明它们是否独立及理由，再给出比较所得的结论和局限 |

逐维列出判据、判分理由及本次会话的原文出处（消息 ID、角色、片段）。决策还须引用最终确认操作，理由可取自确认时或此前明确解释同一选择的用户原话。**0 分须有表中反向行为的直接证据**。该维没有证据能完整支持任何一档时，记 `null`（无法评估）并说明原因，如没有观察机会、只有角色发言、引用无法定位，或只向王宇泛问“你觉得呢”而无核实行为。部分识别只按有原话支持的风险判档，未披露的线索不算遗漏。

例如，用户在 S0 只问王宇“你亲自核实过吗？”就进入 S4。王宇答“没有”后，用户直接确认提前退出训练。按上表试判，主动核实为 2 分，其余三维均为 `null`。用户没有分析答复，也没有作招聘选择。若同一段对话以确认“退出招聘流程”结束，复盘写入这一选择。缺少能归属于该选择的理由，决策合理性仍为 `null`。

四维均可评分时，百分制折算为 `(风险识别 × 25 + 主动核实 × 30 + 决策合理性 × 25 + 证据分析 × 20) / 4`。任一维为 `null` 时总分为 `null`，保留有据的分项，不重分配权重。百分制展示与取整方式**待负责人确认**。

在业务判定与评分中，LLM 仅辅助提取和总结已有对话证据。后端核对原文，按获批规则控制事件、阶段、披露权限和最终决策，并计算分数。模型无权直接修改剧情状态、指定分数，或绕过后端评分规则。
